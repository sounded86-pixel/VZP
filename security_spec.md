# Security Specification (TDD Validation)

## 1. Data Invariants
- **Partners**: Must belong to an authenticated user (`userId == request.auth.uid`). Package selection, status, and agreement boolean must strictly match the types defined in the schema. Standard users can never self-approve.
- **Licenses**: Definitive operational licenses. Can only be issued/updated by administrator roles.
- **Contracts**: Legally binding records signed by residents. The signing user's ID must match their authentication context (`userId == request.auth.uid`). No tampering with immutable fields (like `userId` or `userName`) once signed.
- **Franchise Leads**: Lead requests generated by prospective regional partners. Creation requires a signed-in session; reads/lists are strictly reserved for administrative roles.

## 2. The "Dirty Dozen" Malicious Payloads (Permission Denied Testing)

### Payload 1: Partner Role Elevation / Ghost Field
Standard user attempts to inject an unauthorized administrative field or pre-approve themselves.
```json
{
  "id": "part_malicious",
  "districtName": "Малиновый район",
  "contactName": "Hacker",
  "contactPhone": "+79998887766",
  "selectedPackage": "partner",
  "royaltyModel": "percent",
  "royaltyPercentage": 1,
  "status": "approved", // Attempting self-approval
  "signedAgreement": true,
  "createdAt": "2026-07-12T01:46:33Z",
  "userId": "auth_user_id",
  "ghostField": "maliciousValue"
}
```

### Payload 2: Spoofed Partner User ID
User `A` tries to submit a partner registration representing User `B`.
```json
{
  "id": "part_spoofed",
  "districtName": "Солнечный район",
  "contactName": "Victim",
  "contactPhone": "+79998881111",
  "selectedPackage": "local",
  "royaltyModel": "percent",
  "royaltyPercentage": 5,
  "status": "pending",
  "signedAgreement": true,
  "createdAt": "2026-07-12T01:46:33Z",
  "userId": "victim_user_id" // Spoofed ID
}
```

### Payload 3: Spoofed Contract Signee
User attempts to record a signed legal contract under another user's profile.
```json
{
  "id": "cont_spoofed",
  "userId": "victim_user_id", // Spoofed ID
  "userName": "Victim Name",
  "type": "license",
  "status": "signed",
  "signedAt": "2026-07-12T01:46:33Z",
  "content": "Malicious content..."
}
```

### Payload 4: Arbitrary License Self-Issuance
A non-admin user attempts to insert an active license directly into the `/licenses` collection.
```json
{
  "id": "lic_forged",
  "partnerId": "part_attacker",
  "districtName": "Вельский район",
  "licenseType": "partner",
  "validFrom": "2026-07-12T01:46:33Z",
  "validUntil": "2027-07-12T01:46:33Z",
  "isActive": true,
  "paymentStatus": "paid",
  "createdAt": "2026-07-12T01:46:33Z"
}
```

### Payload 5: Unauthorized Lead Interception (List)
A standard user attempts to read other prospective partners' leads.
`GET /franchise_leads`

### Payload 6: Forged Lead Injection
Lead submission with missing fields or oversized parameters.
```json
{
  "id": "lead_oversized",
  "orgName": "A",
  "regionName": "Oversized Region Name ... [repeats to 10MB]",
  "contactName": "Contact",
  "contactPhone": "+79991112233",
  "contactEmail": "attacker@email.com",
  "selectedPackage": "invalid_pkg"
}
```

### Payload 7: Tampering with Immutable Contract Signature
Attempt to update the signature date of an existing contract.
```json
{
  "signedAt": "2020-01-01T00:00:00Z" // Altering timestamp
}
```

### Payload 8: Contract IP Poisoning
Injecting massive string payload as signee's IP Address to exploit storage boundaries.
```json
{
  "ipAddress": "192.168.1.101..." // Oversized payload
}
```

### Payload 9: Standard User Deleting Partner Profile
Standard user attempts to delete their partner profile after registration.
`DELETE /partners/part_user`

### Payload 10: State Bypass in License Status
Attempting to mark license as `paid` through a public write.
```json
{
  "paymentStatus": "paid"
}
```

### Payload 11: Lead Scraping Attack
Unauthenticated guest session attempting to list franchise leads.
`GET /franchise_leads`

### Payload 12: Partner ID Poisoning
Injecting non-alphanumeric junk characters as a partner path variable.
`POST /partners/part_$$%20_junk`

## 3. Test Verification Suite
All "Dirty Dozen" operations must return `PERMISSION_DENIED` under non-admin conditions. Only valid requests conforming to the structured schema can be recorded in the Firestore DB.
